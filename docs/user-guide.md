# SSE ETF 策略系统 — 功能介绍与使用说明

> 版本 v1.5 ｜ 适用：沪市 ETF（5 开头）、单标的、只做多、日线执行、收盘后日频监控
>
> 本文档面向使用者。技术设计与实现细节见 `docs/wyckoff-strategy-design.md`，部署与安全见 `docs/deployment.md`，AI 策略契约见 `docs/ai-strategy-authoring.md`。

---

## 一、这个系统能做什么

一句话：**把「威科夫量价分析」做成可以回测、可以监控、可以推送的完整流程**。

它解决四个问题：

| 问题 | 系统怎么解决 |
| --- | --- |
| ETF 份额和指数走势看不到一起 | 行情查看页叠加份额与指数双轴对比 |
| 威科夫很主观，不知道阈值怎么定 | 事件识别 + 事件研究，用历史样本统计校准 |
| 策略好不好只能凭感觉 | 回测 + 参数扫描（训练/验证分段） |
| 有信号了但没人提醒 | 收盘后自动检查、飞书/Telegram 推送、双账本模拟跟踪 |

### 核心能力清单

- **行情查看**：ETF 份额 × 指数叠加，支持自定义指数、归一化对比、CSV 导出、收藏
- **Wyckoff 事件识别**：SC / BC / AR / ST / Spring / Test / UTAD / SOS / SOW / LPS / LPSY，附带区间、阶段与置信度
- **事件研究**：统计每个事件确认后 5/10/20/60 日的前瞻收益、胜率、MFE / MAE
- **参数校准**：31 个 Wyckoff 参数可在页面上调整并实时重算
- **策略 DSL**：声明式条件（事件/阶段/周线/份额流），可版本化、可校验
- **回测**：T+1 开盘成交、滑点、佣金、失效取消、分批建仓、完整绩效指标
- **参数扫描**：网格搜索 + 训练/验证分段，按"较差一段"排序降低过拟合误导
- **前复权**：自动识别除息跳空，人工确认后统一复权，避免长周期收益失真
- **双账本模拟盘**：规则自动账本 + 人工确认账本，并列对比
- **收盘后监控**：价格类 15:10、含份额 18:40（重试至 22:00）、信号去重
- **通知**：飞书群机器人 / Telegram，候选语义、失败重试、发送日志
- **AI 助手**：接入任意 OpenAI 兼容模型，分析行情、生成策略、自动校验存草稿
- **策略管理**：版本历史、来源溯源、一键启用、版本绑定回测

### 明确不做什么

- 不做实盘自动下单（没有券商 API）
- 不做空、不加杠杆、不支持期权期货
- 不做盘中分钟级触发（日线级别，止损按收盘确认、次日开盘执行）
- 不覆盖深交所 ETF（159 开头）与已退市产品

## 二、快速开始

### 前置要求

Node.js ≥ 22.5（用到内置 `node:sqlite`）。

### 启动

```bash
pnpm install
pnpm dev        # 开发：http://127.0.0.1:5173
pnpm test       # 运行测试
```

生产：

```bash
pnpm build
APP_SECRET_KEY=<随机串> pnpm start   # http://127.0.0.1:8765
```

> 生产默认只监听 `127.0.0.1`。要对外提供服务，**必须先设置 `APP_AUTH_TOKEN`**，否则任何人都能调用接口（包括消耗你的 AI 额度）。

## 三、页面使用说明

### 3.1 行情查看

看 ETF 份额变化与指数走势的关系。

**怎么用**

1. 输入 ETF 代码或关键词（如 `510300` / `沪深300`），回车或点「查询」
2. 选时间范围（近 1 月 ~ 近 5 年，或自定义区间）
3. 选叠加指数（默认上证指数，支持内置清单或任意 6 位代码）
4. 点 ☆ 或按 `F` 收藏当前 ETF，收藏项显示在输入框下方

**读图**

- 蓝色线：ETF 总份额（亿份），看一级市场资金进出
- 橙色线：叠加指数，看价格走势
- 下方柱状：份额日变化，**红色 = 净申购**（资金进场），绿色 = 净赎回
- 「归一化（起点=100）」：把两条不同量纲的线放到同一尺度比较相对涨幅

**注意**

- 份额是 T 日晚间发布，**盘中看不到当日份额**
- 只覆盖沪市 ETF，深交所 159 开头不支持
- 首次查询长区间要按日拉取上交所数据，较慢；之后走本地缓存秒开

### 3.2 策略研究（核心页面）

**一条完整的研究路径：**

```
选标的 → 识别事件 → 看事件研究 → 调参数 → 参数扫描 → 回测 → 判断
```

#### 第一步：识别事件

1. 输入 ETF 代码，选时间范围（建议先用近 3–5 年，样本更多）
2. 可选「纳入份额流」——把 ETF 净申购/赎回作为供需证据，但会慢一些
3. 点「识别事件」

**输出什么**

- 顶部卡片：K 线根数、事件数、区间数、当前阶段与置信度
- 事件标签：每类事件出现次数
- K 线图：事件 marker + 吸筹/派发区间框 + 成交量
- 右侧事件明细表：发生日、**确认日**、价格、区间、量能证据

> **看不懂某个事件？** 事件名后面有个 ⓘ 图标，点一下弹出解释：中文名、英文原名、吸筹/派发归属、**具体识别条件**（对应哪些参数）、以及**该怎么用**。事件标签栏、事件明细表、事件研究表里的所有事件名都有这个图标；监控页的候选信号同样有。

**11 个事件速查**

| 事件 | 中文 | 方向 | 一句话 |
| --- | --- | --- | --- |
| SC | 卖出高潮 | 吸筹 | 下跌末端放量恐慌抛售，长下影收回 |
| BC | 买入高潮 | 派发 | 上涨末端放量抢筹，上影出货 |
| AR | 自动反弹/回落 | 结构 | 高潮后的反向走势，用来划定区间 |
| ST | 二次测试 | 结构 | 再回关键价位但量能衰减 |
| Spring | 弹簧/诱空 | 吸筹 | 假跌破下沿又收回 |
| Test | 测试 | 吸筹 | Spring 后缩量回踩确认供给枯竭 |
| UTAD | 派发后上冲 | 派发 | 假突破上沿又跌回 |
| SOS | 强势信号 | 吸筹 | 放量宽振幅突破上沿 |
| SOW | 弱势信号 | 派发 | 放量收阴跌破下沿 |
| LPS | 最后支撑点 | 吸筹 | SOS 后缩量回踩上沿不破 |
| LPSY | 最后供给点 | 派发 | SOW 后缩量反弹下沿失败 |

> **重要**：图表 marker 用的是**确认日**不是发生日。Spring 可能今天跌破、两天后才确认收回，信号以确认日为准——这是回测和实盘一致的前提。

#### 第二步：看事件研究

表格统计每个事件确认后（次日开盘买入）在 5/10/20/60 日的表现：

- **样本**：出现过多少次。样本 < 10 的结论不可信
- **平均收益 / 中位数**：两者差很多说明有异常值
- **胜率**：上涨比例
- **MFE / MAE**：期间最大浮盈 / 最大浮亏，用来估止损位

**怎么读**：先看样本量，再看收益方向是否稳定。如果某事件只有 2 个样本、收益 +5%，不要信。

#### 第三步：调 Wyckoff 参数

「Wyckoff 参数」面板分四组，共 31 项。**每项标题可悬停看说明**，分组标题会显示「几项已改」。

| 组 | 关键参数 | 调大后的效果 |
| --- | --- | --- |
| 结构与区间 | ZigZag 阈值、区间最短宽度、最少触碰 | 区间更少更大 |
| 量能与高潮 | 量能 Z 窗口、SC/BC 量能阈值 | 高潮事件更少 |
| 反弹/测试/弹簧 | Spring 破位幅度、确认根数 | Spring 更宽松或更严格 |
| 强弱信号/回踩 | SOS/SOW 振幅与突破 | 突破信号更少 |

改完点「识别事件」重算。参数自动存浏览器本地，刷新不丢；「恢复默认」回到校准值。

**不知道设什么合适？** 用下面的「参数推荐」。

#### 第三步补充：参数推荐（一键给出建议值）

面板就在 Wyckoff 参数下面。点「给出建议」，系统会：

1. 用**当前标的**的历史事件样本，对每类事件小范围扫一遍阈值（例如 Spring 破位 × 确认根数 = 9 组）
2. 按事件研究的前瞻收益打分，在**训练段**选出最优组合
3. 在**验证段**复核，并把两段样本量、均值一并列出
4. 只列「改善足够大」的分组，其余标为「当前值已足够」或「样本不足」

打分口径：`(均值 + 中位数)/2 × n/(n+8)`。后半段是小样本收缩——样本越少分数越向 0 靠，避免「2 个样本 +8%」被当成最优。

**几个可调项**

| 项 | 含义 | 建议 |
| --- | --- | --- |
| 前瞻窗口 | 事件确认后看多少天 | 做波段用 10 日，做中长线用 20 日 |
| 最少样本 | 低于这个样本量不给建议 | 默认 5；调到 3 只能当线索 |
| 训练截止 | 训练段结束日，之后是验证段 | 默认区间 70% 处 |
| 只算这些分组 | 只扫关心的几类事件 | 默认全部 |

**怎么用结果**

- 点「套用建议」把建议值写进参数面板，再点「识别事件」重算
- 蓝色标签 = 与当前值不同、会被改动；灰色 = 与当前值相同
- 「当前值已足够」表示最优候选比当前值只好一点点（< 0.2 个百分点），不值得改

> 推荐是**启发式**：样本量通常只有个位数到几十，结论方向性参考。套用后请用事件研究 + 回测验证，别把建议当结论。

**手工调参建议**：一次只改一个参数，观察事件数量和事件研究统计的变化。

#### 第四步：参数扫描（防过拟合）

选 1–3 个参数轴，设定「训练截止」日期，点「开始扫描」。

系统会：

1. 在**训练段**跑所有参数组合
2. 在**验证段**检验表现
3. 按**两段中较差的一段**排序

**为什么这样排**：如果只看训练段收益，一定会选出过拟合的参数。按较差一段排序，选出来的是"两段都不难看"的组合。

> 扫描只做排序和对比，**不会自动替你选定参数**。样本量通常很小，最后一步要你自己判断。

#### 第五步：回测

选模板（Spring 吸筹反转 / SOS 突破持有）、设初始资金，点「运行回测」。

**输出**

- 指标卡片：总收益、年化、最大回撤、夏普、胜率、最终净值
- 净值曲线：策略 vs 买入持有 vs 回撤
- 交易明细：成交日、信号日、价格、数量、手续费、盈亏、原因

**成交口径**（和监控完全一致）

- T 日收盘出信号 → **T+1 开盘价成交**
- 含滑点、佣金、最低 5 元、100 份整数倍
- **T+1 限制**：当日买入当日不可卖
- **开盘失效取消**：次日开盘已跌破结构失效位则取消入场，并进入 5 天冷却

#### 除息事件 / 复权

K 线原始数据**不复权**，ETF 分红会在除息日留下向下跳空。实测影响很大：

| 510880（红利ETF）十年买入持有 | 收益 |
| --- | --- |
| 未复权 | 25.31% |
| 前复权 | 76.13% |

**使用方法**

1. 点「自动识别」，系统对比 ETF 与上证指数的额外低开，列出候选除息日
2. **逐条确认**——自动识别是启发式的，可能把真实利空误判成除息
3. 确认后，K 线、事件研究、回测、AI 上下文**统一使用前复权价格**

> 未确认的记录不参与复权。这个设计是刻意的：宁可少调，不能错调。

### 3.3 策略管理

看所有策略及其版本。

**列表**：策略名、标的、启停开关、更新时间

**详情抽屉**（点「详情」）：

- 基本信息：标的、引擎、启用状态、入场/出场条件 JSON
- **版本历史**：每个版本的状态（草稿/已校验/启用中/已归档）、校验结果、**来源**（AI 模型名或人工）、创建时间
- **回测记录**：区间、收益、基准、回撤、**复权口径**、绑定的版本 ID

**操作**

- **校验**：草稿版本检查结构合法性
- **启用**：把版本设为 active，同时启用策略、同步配置（同一策略只能有一个 active）
- **回测**：按该版本跑近 1 年回测

**为什么版本化**：策略内容不可变，改动产生新版本。这样历史回测永远能按当时的版本和数据口径复现。

### 3.4 AI 助手

用大模型分析行情、生成策略。

#### 配置模型

点「模型设置」，填：

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| Base URL | OpenAI 兼容端点，一般填到 `/v1` | `https://api.deepseek.com` |
| Model | 模型名 | `deepseek-chat` |
| API Key | 可选，本地 Ollama 可留空 | `sk-...` |
| Temperature | 0–2，策略生成建议 0.2–0.4 | `0.3` |
| Max Tokens | 单次输出上限 | `2048` |

支持的服务商：OpenAI、DeepSeek、Moonshot、通义、智谱、本地 Ollama / vLLM 等，只要兼容 `/chat/completions`。

点「测试连接」验证；保存后可看到**近 30 天用量**（调用次数、失败数、输入/输出 token）。

> API Key 保存在服务端，接口返回时脱敏。配置了 `APP_SECRET_KEY` 时加密存储。

#### 三个按钮

- **分析数据**：把当前标的的阶段、区间、最近事件、事件研究、60 根日 K 压缩后发给模型，输出结构化分析
- **生成策略**：要求模型输出 Wyckoff DSL JSON，服务端解析并校验；通过后**自动存为草稿版本**
- **发送追问**：基于上一次的行情上下文继续对话

#### 生成策略的约束

模型被要求遵守：

- 只做多，`riskBased` 仓位必须含 `stopLoss`
- `fillAt` 只能是 `nextOpen`
- 不支持未实现节点（如 `takeProfit`）
- 事件/阶段必须从白名单里选

**校验不通过时**：错误会列在策略面板上，可以继续追问让模型修正。

**校验通过后**：显示「草稿 v1」，可以「回测此版本」或「启用策略」。

> AI 输出被当作**数据**处理，不会执行任意代码。当前只接受 DSL JSON。

### 3.5 监控

收盘后自动检查信号、驱动模拟盘、发送通知。

#### 顶部状态

- **调度运行中 / 调度未启动**：开发环境不启动自动调度（避免误触发），生产 `pnpm start` 后自动运行
- **检查时点**：价格类 15:10；含份额 18:40（重试至 22:00）

#### 四个 Tab

**候选信号**

每行一条信号：确认日、事件、动作（买入/离场观察）、参考价、区间、**失效位**、状态。

- 状态「候选」时可点**确认**或**忽略**
- 确认 → 信号进**人工账本**，生成待成交订单
- 忽略 → 只改状态，不产生订单

**模拟盘**（两个账本并列）

| 账本 | 谁触发 | 用途 |
| --- | --- | --- |
| 规则账本 | 命中规则自动挂单 | 评估策略本身，不受人工干预 |
| 人工确认账本 | 你点确认才挂单 | 评估人工过滤的增益或损耗 |

对比两个账本的净值差，就能看出"人工过滤"到底加分还是减分。

每个账本显示：现金、持仓、总净值、已实现盈亏、胜率、订单列表。

**通知渠道**

支持飞书群机器人与 Telegram。

- 飞书：填 Webhook URL，可选签名密钥，可开关卡片消息
- Telegram：填 Bot Token 和 Chat ID，`API Base` 可填代理或自建地址

点「测试」发一条测试消息，结果会记在发送记录里。密钥在列表里脱敏显示，编辑时留空则保留原值。

**发送记录**

每次发送的时间、渠道、状态、HTTP 状态码、内容摘要。

#### 信号是怎么产生的

每个交易日收盘后：

1. 拉取最新行情（含复权）
2. 用与回测**完全相同**的分析器与条件求值，判断最新一根 bar 是否触发
3. 同一信号只入库一次（数据库唯一约束），重启不重复
4. 规则账本自动挂单；人工账本等你确认
5. 合并成一条消息推送到所有启用的渠道

**订单怎么结算**

下一次检查时，取信号日之后第一个交易日的开盘价：

- 开盘跌破失效位 → 取消
- 否则按开盘价成交（含滑点、佣金）
- T+1 限制生效
- 落后超过 5 个交易日 → 标记 `missed`，**不伪造成交**

## 四、关键概念

### 事件双时间：发生 vs 确认

每个事件有两个日期：

- **occurredDate**：价格实际发生日（如 Spring 跌破区间的那天）
- **detectedDate**：确认日（如收盘收回区间的那天）

**所有交易、监控、去重都用确认日**。这是避免未来函数的核心——在发生日你并不知道它会收回。

通知里两个日期都会显示，避免误以为是当天刚发生。

### 区间与阶段

- **交易区间**：由 swing 高低点聚类形成，有上下沿和 ID
- **区间方向**：pivot 区间用起点前 60 根涨跌幅判断吸筹（下跌后）或派发（上涨后）
- **阶段状态机**：`accumulation_A~E` / `distribution_A~E` / `markup` / `markdown` / `range` / `neutral`，带置信度

阶段**不硬判**：置信度不够时输出 `range` 或 `neutral`，策略可选择是否要求最低置信度。

### 校准结论（重要）

用 4 只 ETF、10 年数据校准，并用上证指数 + 7 只未参与校准的 ETF 做样本外检验，结论：

| 事件 | 结论 |
| --- | --- |
| **Spring** | 最稳定的多头入场事件，样本内外均为正 |
| **SC** | 有稳定正漂移，但适合作观察/背景，不单独入场 |
| **SOS** | 依赖市场环境，必须叠加周线/相对强弱确认 |
| **LPS / ST** | 单独入场弱，适合做确认与止损参考 |
| **UTAD / SOW / BC** | 在 ETF 长多策略里**不是可靠卖出信号**，只作风险提示 |

**所以**：出场应依赖**结构止损**，而不是"看到派发信号就清仓"。

样本量仍然偏小（Spring 校准集 19 个 + 样本外 13 个），建议每季度复跑校准。

### 复权为什么重要

ETF 分红在除息日留下向下跳空。不复权会有两个后果：

1. 长周期收益被系统性低估（510880 十年差 51 个百分点）
2. 跳空被误识别成派发事件，产生假信号

系统用「ETF 相对基准指数的额外低开」识别除息，人工确认后统一前复权。

## 五、常见操作

### 我想快速验证一个想法

1. 策略研究 → 选标的 → 近 3 年 → 识别事件
2. 看事件研究，确认目标事件有足够样本
3. 选模板跑回测
4. 结果不理想就调参数重算

### 我想让 AI 帮我写策略

1. AI 助手 → 模型设置 → 填 Base URL / Model / Key → 测试连接
2. 输入要求（如"生成一个 Spring 吸筹反转策略，要求周线不空头"）→ 生成策略
3. 看校验结果，不通过就继续追问
4. 通过后「回测此版本」看表现
5. 满意就去策略管理「启用」

### 我想每天收到信号

1. 策略管理 → 确认策略已启用
2. 监控 → 通知渠道 → 新增渠道 → 测试发送
3. 生产环境用 `pnpm start` 常驻运行（详见 `docs/deployment.md`）
4. 每天收盘后会收到候选信号；在监控页确认或忽略

### 我觉得信号太少/太多

- **太少**：放宽对应事件的阈值（如 Spring 破位幅度调大、确认根数调大）
- **太多**：收紧阈值，或在 entry 里叠加更多确认条件（周线、份额流、阶段置信度）
- **注意**：改完一定要在事件研究和回测里验证，不能只看数量

## 六、已知限制

| 限制 | 说明 |
| --- | --- |
| 份额数据 T 日晚间才发布 | 盘中无法用份额因子 |
| 份额仅近 5 年 | 依赖份额的策略回测跨度受限 |
| 仅沪市 ETF | 深交所 159 开头不支持；已退市产品无数据 |
| 除息识别是启发式 | 金额由跳空幅度反推，不等于公告数据 |
| 事件样本量小 | 结论方向性参考，不要当统计显著 |
| 单用户、无角色 | 无多租户、无速率限制、无审计日志 |
| 日频 | 无盘中触发；止损按收盘确认次日开盘执行 |
| 进程需常驻 | 停机期间信号不实时推送，重启后补算最近交易日 |

## 八、风险提示

本系统是**研究工具**，不是投资建议：

- 所有信号都是「候选」，需要人判断
- 历史回测表现不代表未来收益
- 样本量小、参数敏感、过拟合风险始终存在
- 数据来自公开接口，可能有延迟、缺失或错误
- 复权口径、除息识别都是近似处理

**不要**把系统信号当作自动交易指令使用。
